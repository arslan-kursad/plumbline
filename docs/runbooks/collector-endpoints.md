# Runbook — the collector's reachable surface

**Status:** measured 2026-08-26 against the deployed service. One finding here is
**unexplained**, and unexplained is the recorded state rather than a placeholder
for a guess.

Scope is deliberately narrow: which paths reach the collector's container from
outside, and what that means for F4's uptime check. Everything else about the
collector is in [`collector/README.md`](../../collector/README.md) and
architecture §2.1.

## 1. What is reachable, measured

The collector registers exactly two HTTP routes —
[`collector/internal/receiver/http.go`](../../collector/internal/receiver/http.go)
— `HealthPath = "/healthz"` and `TracesPath = "/v1/traces"`, both on Go's
`ServeMux` as exact patterns.

Against `https://collector-<hash>-uc.a.run.app`:

| Path | Response | Reached the container? |
| --- | --- | --- |
| `/healthz` | Google's styled HTML 404 | **No** |
| `/health` | `404 page not found` | Yes — Go's mux, no handler registered |
| `/healthz/` | `404 page not found` | Yes — Go's mux; the exact pattern does not match a trailing slash |
| `/` | `404 page not found` | Yes |
| `/zzz` | `404 page not found` | Yes |
| `/v1/traces` | `405 only POST is accepted` | Yes — the collector's own handler |

**The two witnesses are different and telling them apart is the whole diagnosis.**
`404 page not found` is Go's `http.NotFound`, so the request reached the process.
A styled HTML page from Google's edge never touched your code. F2 decision log
W2.12 records an investigation that cost most of a day partly because a
log-name-encoding mistake made "no request arrived" and "the query was wrong" look
identical.

## 2. The finding: `/healthz` never reaches the container

Ruled out by query rather than by waiting (W2.12): ingress is
`INGRESS_TRAFFIC_ALL`, read back from the API; `allUsers` holds
`roles/run.invoker`, and a missing invoker returns 403 rather than 404; both URL
forms are present in `urls`; `constraints/run.allowedIngress` is effectively
`ALLOW`; the service's `terminalCondition` is `Ready`, `RoutesReady` succeeded,
100% of traffic on the current revision; and an authenticated request behaves the
same as an anonymous one.

Every neighbouring path reaches the container. The exact string `/healthz` does
not. **Why is unknown.** It is a platform behaviour at the Cloud Run edge, it has
persisted across four days and two revisions, and no configuration this repository
owns explains it.

**Not worked around, and that is a decision.** The obvious fix is to move the
collector's health path, and it is the wrong instinct: it would make the local and
cloud surfaces differ for no reason the code expresses, and the next reader would
find a health endpoint at an unusual path with no explanation. The endpoint is not
load-bearing today — Cloud Run's startup probe is a TCP check on the port and it
passes — so this is documented and left alone.

## 3. Consequence for F4's uptime check

F4 needs an uptime check to observe uninterrupted ingest over 14 days. **The
collector currently has no externally reachable path that returns a healthy
response**, and the shape of that problem is worth stating precisely, because it
is one step worse than "bind a different path":

- `/healthz` is the only health route the collector serves, and it is the one path
  the edge intercepts.
- `/health` and `/healthz/` reach the container but the collector registers
  nothing there, so both answer `404`. Binding an uptime check to either would
  monitor a 404 — green only if the check is configured to accept 404, at which
  point it is asserting that Google's edge is up, not that the collector is.

So the uptime check cannot simply be pointed at `/health`. Three options, none
taken here because each is a decision outside this runbook:

1. **Bind to `/v1/traces` and accept `405`.** It works today with no code change:
   the response is generated by the collector's own handler, so a `405` proves the
   container is serving. It is also unusual enough that the binding needs the
   reason written next to it, or the next reader will "fix" it.
2. **Register a second health route at a path the edge does not intercept**
   (`/readyz`, `/-/health`). One line in the collector, and it makes the cloud
   surface differ from local by *addition* rather than by moving something — which
   is a weaker version of the objection in §2, not the same one.
3. **Establish why `/healthz` is intercepted** and address the cause. The only
   option that ends the finding rather than routing around it, and the only one
   that cannot be scheduled, because nothing here explains the behaviour.

**Whichever is chosen, the reason goes next to the binding.** An uptime check
pointed at an odd path with no comment is indistinguishable from a mistake, and
this one would be copied forward.

## 4. Where else this matters

The push-delivery decision tree in
